# Agent Notes

Purpose: pointer authority, keyboard dispatch and placement for the Map. One pure function decides what a press means, one hit test decides what is under a point, one module tells Excalidraw what it may hold selected, one class carries a gesture from begin to end, one listener owns the keys, and one function says where a new Block lands. Design: `docs/design/area-map-rebuild/code.md`, sections "Pointer authority" and "Keyboard".

Files:

- `hit-test.ts` is the one place that decides what is under a scene point. `hitTest(scene, point)` runs over a `VisibleScene` (the composition's elements and region rects, the snapshot's `hiddenIds`, `scopedAreas` and `folded`, and the zoom) and returns a `SceneHit`: the topmost visible authored element (never a region, never an ephemeral or hidden element, bound text resolved to its container), whether the point is `inside` that element's body rather than only its grab padding, and the deepest visible `area`. `visibleSceneFromSnapshot(snapshot)` builds the input; `deepestVisibleArea(scene, point)` answers the Area alone; `selectedVisibleArea(scene, selection)` names the selected region's Area when it is visible; `grabPaddingAt(zoom)` is `LAYOUT.grabPadding` divided by the zoom, floored at `LAYOUT.grabZoomFloor`.
- `press-meaning.ts` exports `PressMeaning`, the closed union from the design, `PressContext`, what a press can see, and `meaningOfPress(context)`, the only decider. `PRESS_RULES` is the nine rules in the design's order, each a named function that answers or passes; a product decision on one rule changes one entry. `PressContext.spaceHeld` is the flag `keyboard-dispatch.ts` keeps. The property test proves the function is total and deterministic, never names a hidden Area, pans whenever Space is held, never moves an ancestor from a press inside a Block, and refuses the selected Area's rotation handle.
- `pointer-session.ts` opens the gesture a meaning names, previews it through the kernel solvers for `move-area` and `resize-area` only, and settles it through the projection. It is the class that replaced twenty pointer refs: `begin(meaning, context)`, `preview(point)`, `settle()`, `end()`.
- `excalidraw-subordination.ts` turns a `PressMeaning` into the selection Excalidraw must hold before its first move frame and applies it through `canvas/projection.ts` with `captureUpdate: "NEVER"`. It and `canvas/projection.ts` are the only writers of `selectedElementIds`; the selection-write-confinement lint holds them to that.
- `nudge.ts` runs an arrow-key move through the same session as a pointer move, so a keyboard move and a pointer move share one path. `keyboard-dispatch.ts` hands it the `Delta<"scene">` from `LAYOUT.nudge` or `LAYOUT.nudgeFast` as the `nudge-selection` command.
- `key-routes.ts` is the pure table behind the dispatcher. `routeKey(press, facts)` returns a `KeyDecision`: `ignored` (composing), `surface` (a surface's own controls handle it), `native` (a text field or Excalidraw keeps it), or `map` with a `KeyCommand` and how much of the event to consume (`stop`, `prevent`, `none`). The order is the product rule: an open surface is asked first (Escape always pops the stack; a modal surface owns every key; a panel owns the keys typed inside it and nothing typed beside it; the placement bar owns Enter and the arrows), then the canvas routes in `CANVAS_ROUTES`, each a named function that answers only for its own key, in the order the old component ran them. The chords are `MAP_KEYS` in `ui/key-bindings.ts`, named once. Add a key by adding a chord there and one route here, in its place in the order.
- `keyboard-dispatch.ts` is the one host keydown listener and the only file the keyboard-confinement lint lets add a key listener to the host, document or window. `installKeyboardDispatch(host, deps)` installs capture-phase keydown and keyup listeners on the host and a blur listener on its window, and returns the uninstall function. It builds a `KeyPress` from the event, reads `deps.facts()` and `deps.surfaceOf(target)`, routes through `key-routes.ts`, consumes the event as the decision says and runs the command through `deps.run`. It keeps the Space flag through `deps.setSpaceHeld`: set on the first keydown of Space outside a text field, cleared on keyup, on blur and on uninstall. Space is only default-prevented, never stopped, so Excalidraw still sees it held and does the pan that rule 1 of `press-meaning.ts` names.
- `placement-point.ts` answers where B, paste and Place land. `placementPoint(camera, viewport, lastPointer)` is the last pointer point when it is inside the visible viewport and the viewport centre otherwise, so it is always on screen. `placementTarget(point, scene)` is `deepestVisibleArea` from `hit-test.ts` at that point, or null when the point is over no visible Area; the caller falls back to the located Area. `placement-point.property.test.ts` proves the point is always inside the viewport and the target is never an Area fold or scope has hidden.

Rules here:

- Nothing outside `press-meaning.ts` interprets a press, and nothing outside `hit-test.ts` measures a point against an element or a region. A module that needs to know what is under a point calls `hitTest` or `deepestVisibleArea`.
- A hit runs over the visible scene only. An element in `hiddenIds`, a region under a folded root, or an Area outside the Only restriction never wins a point.
- `PressContext.selectedArea` comes from `selectedVisibleArea`, so a hidden selected region never reaches the rules.
- Only `keyboard-dispatch.ts` listens for keys, and it touches the event and the host and nothing else: it duck-types the target so its test needs no DOM, and every decision is made in `key-routes.ts` from facts. Feature code never reads a key; it runs a `KeyCommand`.
- Every numeric value is branded; the grab padding is the one screen length that crosses into the scene, through `units/scalar-math.ts` `toSceneLength`. Key distances are `LAYOUT` tokens: `nudge`, `nudgeFast`, `placementStep`, `placementStepFine`.
