# Area Map usability and layout audit

Running record. Written as the audit proceeds so a lost session costs one fix, not the whole audit.

Method: a dynamic workflow fanned nine finder agents across the Map's surfaces, and every candidate finding was handed to an independent verifier told to refute it. Findings below are only those reproduced against running code. Three named defects came from Julian; the rest are the audit's.

Verification harness: `packages/agent-shell/app/server.mjs` booted against a throwaway vault on a free port, with `HOME` and `TREES_ROOT` redirected, and driven in real Chromium through Playwright. Some runs used a copy of Julian's real vault so the Area geometry matched what he actually sees. Nothing touched the live server on port 4321 or the real vault.

## Fixed

### 1. The server rejected the world revision it minted itself (Julian's defect 2)

Commit `78ecd9b6`.

`area-map-world-index.mjs` minted every revision with a sha256 digest encoded as base64url. That alphabet includes `-` and `_`. The same module's `OPAQUE_ID` guard requires an alphanumeric first character. The world revision round-trips to the browser and comes back in the next save, so any revision that began with `-` or `_` was refused by the server that produced it, with 400 `a safe world revision is required`.

Rate: 3.16% of digests, measured over 100,000. Roughly every thirty-second save.

Consequence, which is what Julian actually saw: the failed save blocks the queue, every later edit stacks behind it, a recovery draft is written to IndexedDB, and the next load asks whether to Restore or Discard, naming no cause.

Evidence:
- Julian's telemetry, `~/.tangent/agent-shell-actions.jsonl`: 84 records with `"failureKind":"invalid-request"`, `"status":400`, all with `durationMs` 0 or 1, which places them in the synchronous validation block before any I/O.
- Live capture against the sandbox: the server minted `worldRevision` `_K62_ppPFiDu46wg`, the browser sent it back, and the server rejected it.
- Regression test in `area-map-world-routes.test.mjs` asserts every minted identifier satisfies the guard applied to it. It fails on the previous digest and passes now.

## Confirmed, not yet fixed

### 2. Dragging a child Area can move and violently resize the parent (Julian's defect 1)

Partly reproduced. A press on the dashed top edge of the `desk` Area, on a copy of Julian's real vault, moved the parent `otto/tangent` region by 0,-346 and grew it by 1023 pixels of height from a 40-pixel drag.

What does NOT reproduce, so the simple explanations are ruled out: dragging well inside a child moves the child correctly; dragging within about 10 source pixels of the child's edge still grabs the child; selecting the parent first does not make a later drag inside the child move the parent. An earlier apparent reproduction was an artefact of stale coordinates in the probe script and was discarded.

The remaining suspect is the parent's containment refit after a child is dragged near or past its boundary, not hit-test resolution. Still being pinned down.

### 3. Area name chips are dead handles

Pressing and dragging an Area's name chip does nothing at all. The chip is the one part of an Area region that looks like a handle and reads as its identity, so it is the first thing a person grabs.

## Layout defects visible on first paint

- The drawing toolbar covers the located Area's own name label. On a 1440-wide window the `tangent` label sits underneath it and cannot be read.
- The canvas hint "To move canvas, hold mouse wheel or spacebar while dragging, or use the hand tool" is painted across the middle of the map and overlaps Area name chips.

## Pre-existing, not caused by this work

`packages/agent-shell/app/area-map-http.test.mjs` fails on `map-usability` at `3857e5a2`, before any change here: an Area status reads `active` where the test expects `done`. Confirmed by running the test on the unmodified files from HEAD.
