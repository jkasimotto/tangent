# Product Logic

## Why Trees Matter

Trees are the user’s mental geography for parallel work. A path like `project/feature/api` is easier to scan, resume, delegate, and checkpoint than a flat terminal list.

## Why pa Failed

`pa` had useful work organization, but status, attention, and checkpoint data came from hacks and side channels: `.state`, `.tokens`, `.label`, `current_pulse.conf`, and `pulses.jsonl`.

## Why Observations

Reliable attention requires knowing where facts came from, with confidence and evidence. Trees records observed facts as typed observations/events, then derives status and attention from projections.

## Why Not Only Terminal

Terminal is still required for command-line power, but the command center must let the user inspect and intervene without losing global overview.

## What V1 Is

V1 is an agent/worktree command center: semantic tree entities, optional Git worktrees, tmux/process terminal runtimes, agent runs, work sessions, captures, and deterministic attention.

## What V1 Is Not

V1 is not a full project-memory, daily-planning, ownership, estimation, or review-management system.

## Future Project Management

Entities, WorkSessions, Checkpoints, Captures, Usage links, and AttentionItems are intentionally rollup-able by subtree, time, owner, and status later.
