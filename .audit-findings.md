# Area Map usability and layout audit

## Method

Julian asked for a dynamic workflow, so the audit ran as one. Nine finder agents fanned out across the Map's surfaces and interactions. Every candidate finding was then handed to an independent verifier whose instruction was to refute it and to default to refuted when unsure. Fifty-six agents raised 47 findings; 39 survived verification and 8 were refuted.

Verifiers did not accept code reading as proof. Most reproduced their finding in real Chromium against the repository's own fixtures, and several corrected the reporter's diagnosis or rejected the reporter's proposed fix as wrong. Those corrections are recorded with each finding and were followed in preference to the original suggestion.

Harness: `packages/agent-shell/app/server.mjs` booted against a throwaway vault on a free port with `HOME` and `TREES_ROOT` redirected, driven through Playwright. Some runs used a copy of Julian's real vault so the Area geometry matched what he actually sees. Nothing touched the live server on port 4321 or the real vault.

## Julian's three named defects

**1. Dragging a subarea drags the parent.** Confirmed, cause found. `spatialAuthoredHit` in `area-map-world.jsx` matches any non-region element within ten screen pixels of the pointer. The switch of selection to the sub-Area under the cursor is conditional on there being no such hit, so a press anywhere near a Block, a bound label or an arrow leaves the previous selection in place. The Map's own gesture code then declines to run, while Excalidraw has already begun dragging what was selected, which is the ancestor. On release the geometry is discarded and the parent snaps back, so nothing is saved. The verifier reproduced it frame by frame and found it is broader than reported: pressing directly on a Block does the same, which is why it reads as the first grab glitching.

**2. Saving fails and offers discard or restore.** Fixed. See the first entry under Fixed below. The prompt itself remains a separate defect and is listed under Not fixed.

**3. Icons must be images, not drawings.** Done. Note that the finders' icon items are recorded as refuted, because the code did exactly what its design document said: images were deliberately rejected. Julian overruled that decision, so this was a product change rather than a bug fix.

## Fixed

Each carries a regression test that fails without the change.

- **The server rejected the world revision it minted itself.** `78ecd9b6`. Revisions were a sha256 digest in base64url, an alphabet that includes `-` and `_`, while the module's own `OPAQUE_ID` guard demands an alphanumeric first character. The revision round-trips through the browser, so 3.16% of saves were refused by the server that produced them, with 400 `a safe world revision is required`. Julian's telemetry holds 84 of these. Reproduced live: the server minted `_K62_ppPFiDu46wg` and then rejected it.
- **Map icons can be images.** `d88bd1b7`. `.png`, `.svg`, `.webp`, `.jpg` and `.jpeg` beside `.excalidraw`, with intrinsic size read from the file header so no image dependency was added. The `map-kinds.md` definition shape is unchanged and existing drawings keep working. Excalidraw already inverts image elements under its dark theme, so a raster icon is registered as supplied and an SVG is rasterized once to join the same path.
- **An unanswered recovery offer is no longer deleted by the next successful save.** `8b6f285c`.
- **A figure's icon and caption stay inside their Block at every size.** `00dadf71`. The icon square was driven by height alone, so a narrow tall Block threw its icon and caption onto the neighbours.
- **The open Resources panel no longer covers the Map's controls.** `78280179`. Five findings, one cause: the panel width was retyped in every right-anchored rule. One token now defines it and one inset applies it everywhere.
- **A long Block label breaks instead of being clipped.** `94f8bf71`.

## Not fixed

Twenty-two of the remaining findings are in `packages/agent-shell/app/browser/area-map-world.jsx`, a single 3,092-line component that owns pointer gestures, the save and recovery surfaces, the Resources panel, the Outline, the Block picker, every dialog, keyboard handling, toasts and the camera. They cannot be fanned out to parallel agents because they share one file.

Blockers still open at the time of writing are listed first. See git log for anything that landed after this file was last written.

- Text you type and ink you draw are invisible in the Map's dark theme, contrast 1.06:1, because the item defaults are not passed through `themeInkColor`.
- Dragging inside a folded Area silently moves a hidden descendant Area and writes it to the vault.
- Pressing on a sub-Area while its parent is selected drags the parent's outline and saves nothing. Julian's defect 1.
- Restore or Discard names no cause, and every button offered after a save failure is a dead end.
- Place on Map, the placement preview, and Fit and centre all land behind the open Resources panel.
- The documented Space-drag pan folds the selected Area and drags it instead.
- A Block placed while an Area is folded lands in a hidden Area and vanishes.
- Blocks the Map has hidden still block Area drags, creating invisible dead zones.
- Wheel zoom and wheel pan stop dead over an Area name label, and the name pills swallow pointer-down, so an Area cannot be dragged by its name.
- A rubber-band selection started inside an Area moves the Area instead of selecting Blocks.
- Escape closes the whole Resources sheet rather than the intended back-step, and strands the Add-back dialog over an inert Map.
- Only the first Block-picker result is reachable by keyboard; the Outline opens without focus and is sixteen tab stops away.
- Several messages print internal failure codes as their headline, and the map toast never clears.
- After panning or zooming without moving the mouse, B and paste place into an off-screen Area.

## What the shape of these defects says about the code

The code is not a mess. It carries roughly 180 test files in one app directory, real-Chromium tests, property tests, a pre-commit lint that requires a docstring on every function, ADRs and governance lints. Eight findings were refuted precisely because the code already handled the case the reporter suspected.

The defects are concentrated, and four causes account for most of them.

1. **Nothing asserts that what the code mints satisfies the guards the code applies.** The save failure was two constants ten lines apart in one file that had never been reconciled. A single property test would have caught it. The repository already uses that pattern in `area-map-containment.property.test.js`; it is simply not applied where a value round-trips out to a client and back.
2. **One component owns the whole Map.** Twenty-two of 39 findings are in `area-map-world.jsx`. Ambiguous Escape handling, hand-rolled focus restoration per surface, and ad hoc overlay ordering are all consequences of one scope holding roughly forty pieces of state.
3. **Two systems own pointer input with no explicit handoff.** Excalidraw decides what to drag from its own selection at pointer-down; the Map separately decides what the gesture means. Julian's drag defect is that seam failing. There is no single authority answering what a press means.
4. **Layout constants are copied rather than named.** `min(680px, 72%)` was retyped per rule, so each new surface silently forgot it, which produced five findings. The bare `40` and `24` in the figure geometry were the same shape of mistake.

About a third of the findings are not architectural at all. They are messages that print internal codes at a person and dialogs whose two buttons do not say what they do.

## Pre-existing failures, not caused by this work

Both were confirmed by restoring the unmodified files from `HEAD` and re-running.

- `packages/agent-shell/app/area-map-http.test.mjs`: an Area status reads `active` where the test expects `done`.
- `packages/agent-shell/app/area-board-browser.test.mjs`, `compact header focus reaches #for-you-button in visible order`.
